# AX 채용정보 Agent Pipeline — Development Rules

> 이 문서는 프로젝트 진행 중 새로 합의되는 **코딩 규칙, Notebook 작성 규칙, Agent 작업 규칙**을 계속 누적하는 기준 문서입니다.

## 1. Notebook 기본 작업 단위

모든 Notebook 작업은 반드시 아래 3개를 **하나의 세트**로 진행합니다.

### 1) 작업계획 — Markdown Cell

코드를 작성하기 전에 이번 작업의 목적과 확인할 내용을 먼저 적습니다.

예:

```markdown
## 작업계획

- 이번 단계에서 확인할 것:
- 사용할 데이터:
- 실행할 작업:
- 예상 결과:
- 다음 단계로 넘어가기 위한 조건:
```

### 2) 실제 코드 — Code Cell

현재 작업계획에 필요한 코드만 작성합니다.

원칙:
- 한 번에 너무 많은 작업을 넣지 않습니다.
- 현재 STEP 범위만 구현합니다.
- 다음 STEP 코드를 미리 작성하지 않습니다.
- 결과를 사람이 확인할 수 있도록 필요한 출력은 남깁니다.

### 3) 실행 결과 해석 / 분석 요약 — Markdown Cell

코드 실행 후 결과를 사람이 직접 확인하고 해석합니다.

반드시 아래 내용을 확인합니다.

```markdown
## 실행 결과 해석 / 분석 요약

- 무엇이 나왔는가?
- 예상과 같은가?
- 데이터 관점에서 어떤 의미인가?
- 이상한 값이나 추가 확인이 필요한 부분은 있는가?
- 다음 단계로 넘어가도 되는가?
```

---

## 2. 핵심 원칙

Notebook의 기본 흐름은 항상 다음과 같습니다.

```text
작업계획
→ 실제 코드
→ 실행
→ 결과 확인
→ 결과 해석 / 분석 요약
→ 다음 작업
```

코드만 작성하고 넘어가지 않습니다.

특히 데이터 분석 프로젝트에서는 **코드 작성 자체보다 결과를 읽고 설명하는 과정**을 동일하게 중요하게 봅니다.

---

## 3. 앞으로 규칙을 추가하는 방법

프로젝트 진행 중 새로운 규칙이 생기면 이 문서에 계속 추가합니다.

예:

- 변수명 규칙
- 함수명 규칙
- 주석 작성 규칙
- DataFrame 컬럼명 규칙
- 파일명 규칙
- 함수 분리 기준
- 예외 처리 규칙
- 로그 작성 규칙
- 테스트 규칙
- Agent 작업 범위 규칙
- Git Commit 규칙

새 규칙은 반드시 다음 형식으로 기록합니다.

```markdown
## 규칙명

### 규칙
무엇을 어떻게 할 것인지

### 이유
왜 이 규칙을 사용하는지

### 예시
좋은 예 / 피해야 할 예
```

---

## 4. 현재 확정된 규칙

### Rule 01. Notebook 3단위 작성 규칙

모든 Notebook 작업은 아래 3개를 하나의 단위로 작성합니다.

1. 작업계획 — Markdown Cell
2. 실제 코드 — Code Cell
3. 실행 결과 해석 / 분석 요약 — Markdown Cell

이 규칙은 특별한 이유가 없는 한 모든 STEP에 적용합니다.
